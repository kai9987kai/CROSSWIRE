# Independently checkable evidence and conservative recovery

## Intent
Advance CROSSWIRE as a CPU-local synthetic interoperability instrument. The audit found that recovery could execute a hazardous action and label it safe, the browser study ignored selected controls, and analysis could mix escalation conditions. Fix those defects and add public evidence checking independent of the candidate search implementation.

## Approach and boundaries
Considered additional probe policies, additional fixture families, and stronger evidence checking. Choose evidence checking because current safety and comparison claims need stronger support before expanding the search methods. This is an implementation choice under the user's whole-project improvement request; preserve Python and the no-build browser workbench.

Generate a public-model certificate by independently enumerating static/latency-1 mappings and replaying the supplied calibration evidence. Check the exact surviving set, then check every branch of an admitted robust policy or every step of an admitted word. For contradiction, produce a deletion-minimal subset of public observations/anchors that excludes the entire declared finite class. Unresolved and diagnostic baselines must never masquerade as safety proofs. Certificates neither authenticate observations nor prove latent semantics, real-world safety, or algorithmic novelty.

Recovery dispatch requires a nonempty consistent belief, a remaining horizon, and an action with zero modeled hazards under every survivor. Its response must remain model-consistent. Contradicted beliefs cause abstention; a minimum-risk action is not a safe fallback. Preserve cost and error histories.

Preserve execution mode, temporal/escalation setting, anchors, split and horizon in summaries and pairing. Track completed calibration prefixes and all work before/after escalation. Wire browser settings to real run/study requests, show certificate scope and experimental conditions, and retain cancellation across receipt operations.

## Acceptance
Adversarial tests reject omitted survivors, forged admission, invalid branches, false contradiction, unsafe fallback, exhausted horizon and cross-condition pairing. Fresh receipts must replay exactly; CLI public checks must run without contacting a target. Validate the actual browser workflow, full pytest suite, and package build. Preserve historical receipts with source-revision warnings and replace unsupported documentation claims with current evidence.
